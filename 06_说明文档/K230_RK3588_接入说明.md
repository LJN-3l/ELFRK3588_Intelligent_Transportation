# K230 / RK3588 接入说明

## 推荐落地方案

现阶段建议先用这条链路：

`K230 摄像头采集 -> UART2/CH340 -> RK3588 串流 -> RK3588 跑 YOLO 与网页审核`

原因很直接：

- `K230` 现在最稳的是采集和传流。
- 你的双模型逻辑、人工审核、报告生成，更适合先放在 `RK3588`。
- 如果后面一定要把 YOLO 原生部署到 `K230`，需要先把模型转成 `kmodel`，再改成 `CanMV/KPU` 推理流程，这一步比 RK3588 方案重很多。

## 这次已经补好的能力

- `red_light_violation_prototype.py`
  - 本地抓拍后可选自动上传到网页服务。
- `red_light_violation_gui.py`
  - 新增 `网页接口地址` 与 `来源标识`。
- `rk3588_violation_dashboard.py`
  - 接收桌面端上传的违章图片和元数据。
  - 保存到本地数据库和图片目录。
  - 页面人工审核：确认违规 / 驳回 / 标记重复。
  - 生成文字报告。
  - 可直接读取 `http://127.0.0.1:5001/video` 做在线 YOLO 分析。

## RK3588 端准备

把下面文件拷到 RK3588 同一目录：

- `rk3588_violation_dashboard.py`
- `red_light_violation_prototype.py`

建议模型放在：

- `/root/models/yolo11n.pt`
- `/root/models/yolov11n_hemlet.pt`

准备一个直播 ROI 文件，例如 `/root/live_roi.json`：

```json
{
  "traffic_light_roi": [100, 50, 80, 140],
  "crosswalk_polygon": [[220, 420], [900, 420], [1120, 700], [80, 700]]
}
```

## RK3588 启动顺序

先启动你的串流服务：

```bash
python3 /root/mjpeg_server.py
```

再启动网页服务：

```bash
export LIVE_STREAM_URL=http://127.0.0.1:5001/video
export LIVE_STATUS_URL=http://127.0.0.1:5001/status
export LIVE_BASE_MODEL=/root/models/yolo11n.pt
export LIVE_HELMET_MODEL=/root/models/yolov11n_hemlet.pt
export LIVE_ROI_JSON=/root/live_roi.json
python3 /root/rk3588_violation_dashboard.py
```

浏览器打开：

```text
http://你的RK3588IP:5000
```

## 桌面客户端怎么接网页

打开桌面版 GUI 后：

- `网页接口地址` 填：`http://你的RK3588IP:5000`
- `来源标识` 可填：`desktop_batch`

这样每次抓拍到的违章图，都会自动推到网页审核队列。

## 网页接口说明

- `GET /`
  - 审核中心主页
- `GET /video_proxy`
  - 原始 K230 串流代理
- `GET /live_overlay_feed`
  - RK3588 在线 YOLO 叠加画面
- `POST /api/upload_violation`
  - 接收桌面端或别的客户端上传的违章事件
- `POST /api/events/<id>/review`
  - 人工审核事件
- `POST /api/report/generate`
  - 生成报告

## 如果后面一定要 YOLO 原生跑在 K230

建议分两步走：

1. 先把当前这套网页审核链路跑通。
2. 再把 `基础模型` 和 `头盔模型` 分别转成 `K230 kmodel`，在 K230 侧只输出：
   - 目标框
   - 置信度
   - 违规原因
   - 抓拍小图或图像 ID

到那时，UART 就不必传整帧 JPEG 了，只传结构化结果，速度和稳定性都会更好。
